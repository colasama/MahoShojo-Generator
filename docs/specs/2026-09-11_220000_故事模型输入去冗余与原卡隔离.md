# 故事模型输入去冗余与原卡隔离

状态：已接受，分批实施。日期：2026-09-11。
适用：Arena 普通/流式战报、多人共用的 Hosted runtime，以及连续战报与升华的相关投影。
上位约束：[平台复杂度预算](../decisions/2026-09-01_193200_平台复杂度预算与故障降级决策.md)。

## 数据边界

完整数据卡继续用于验签、原生性判断、编辑、同步、导出、战后更新和备份。
`packages/domain/src/story-prompt-data.ts` 是模型输入专用的纯函数投影，不得写回原卡。
`stripBattleSelectionTransportMeta` 继续只负责选卡传输字段，不扩张为正文裁剪器。

## 已实施的基础投影

- 角色、结构化主/辅助情景、素材剥离 templateId、签名、已知卡片 metadata、创作输入、预设标记、传输统计与已知往返备份。
- adjudicationEvents 只交给已有判定器；正文只接收判定结果，不从嵌套配置自行判定。随机算法、种子、重试和结果返回不变。
- 普通战报核心 JSON 不再携带 arena_history/current_state；独立块遵守读取开关、历史筛选和条数上限。
- userAnswers 独立格式化且只出现一次，兜底角色也遵守严格排位的关闭开关。
- buildState 以“角色参数”输出；保留规则标识、版本、输入与派生数值，剥离 rules[].validationSummary。
- _battle_story 留在原卡供章节规划解析，不作为情景正文传入模型。
- 仅处理已知 schema 路径；不递归按 metadata/author/下划线等通用名称删除用户自定义嵌套设定，不改写 Markdown 字符串。
- 不把 0、false 或未知扩展当作空值丢弃；不因文本相似就合并不同角色/事件。

## 验收与非目标

`packages/domain/tests/story-prompt-data.test.ts` 保护不变性、规则参数和自定义字段；
`packages/hosted-runtime/tests/arena-prompt-projection.test.ts` 保护单次注入、历史上限与严格排位；Web 原有完整 Prompt parity 继续生效。
不变更 wire/schema、原卡存储、权限或安全审核政策；裁剪不是提示注入防护的替代品。
